## Essence Card

### 1. 한 문장 정신 모델

`async` 는 **내려오는 즉시 실행**(순서 보장 없음), `defer` 는 **DOM 완성 직후 문서 순서대로 실행**이다.

### 2. 이 개념으로 AI 에게 시킬 수 있는 것 · 산출물에서 검사할 수 있는 것

- 외부 `<script>` 가 HTML 파싱을 멈추지 않게 `async` 또는 `defer` 를 붙이게 할 수 있다
- 서로 독립적인 추적 스크립트에는 `async`, 초기화 스크립트에는 `defer` 를 쓰게 할 수 있다
- 라이브러리 → 내 코드처럼 의존 관계가 있는 파일에 `async` 가 걸려 있지 않은지 검사할 수 있다
- `defer` 스크립트가 `DOMContentLoaded` 핸들러 없이 요소를 조회해도 되는지 검사할 수 있다
- 속성 없는 기본 `<script>` (파싱 중단) 가 남아 있지 않은지 검사할 수 있다

### 3. AI 협업 패턴

**작성 지시**

```text
async / defer 를 사용해 외부 스크립트 로딩을 만들어줘.

제약:
- `src` 없는 인라인 스크립트에는 붙이지 않는다 — 무시된다
- 라이브러리 → 내 코드처럼 순서가 필요한 파일은 `defer`, `async` 는 서로 독립적인 스크립트에만
- 둘 다 다운로드는 병렬이다 — 차이는 실행 시점과 순서뿐이니 속도를 이유로 고르지 않는다
- 속성 없는 기본 `<script>` 는 피한다
- 수정 후 각 스크립트에 어느 속성을 왜 골랐는지를 한 줄로 설명
```

**오류 수정 지시**

```text
다음 async / defer 오류를 수정해줘.

확인 순서:
1. 여러 파일에 `async` 를 걸었는지 — 의존 관계가 있으면 `defer` 로 바꾼다
2. 속성을 붙인 스크립트에 `src` 가 있는지 — 인라인이면 속성이 무시된다
3. 속성 없는 `<script>` 가 남아 파싱을 중단시키는지

수정 시 오류 원인 · 최소 수정안 · 바뀐 스크립트 실행 순서 만 설명.
```

### 4. 문제 해결 레버 (증상 → 먼저 확인할 것)

- **의존 관계가 있는 코드가 순서를 잃는다** → 여러 파일에 `async` 를 걸었는지. 라이브러리 → 내 코드 순서가 필요하면 `defer`
- **`async` / `defer` 를 붙였는데 무시된다** → `src` 없는 인라인 스크립트인지
- **스크립트 때문에 HTML 파싱이 멈춘다** → 속성 없는 기본 `<script>` 인지 — 피한다
